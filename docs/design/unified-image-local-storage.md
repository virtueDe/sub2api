# 图片统一存储：S3 / 本地目录

## 目标与范围

在现有后台“异步图片对象存储”区域增加存储位置选择：CF R2 / S3 或本地目录。原有启用开关继续控制图片存储；存储位置统一作用于现有异步结果转存、同步 OpenAI URL 结果转存、OpenAI/Grok 输入图片与 mask 代理。原有透传响应维持透传，不新增转存场景。数据库备份继续使用自己的 S3 配置。

先完成开发、自动化验证和独立审查；用户已授权验证通过后合并 main、推送新版本并更新线上。发布不自动更改当前生效的图片存储位置，管理员可在后台切换。

## 后台配置与兼容

| 配置 | 默认值 | 行为 |
| --- | --- | --- |
| `backend` | `s3` | `s3` / `local`；旧设置没有该字段时仍使用 S3 |
| `local_public_base_url` | 空 | 本地下载入口的公开 HTTP(S) 域名；启用本地存储时必填 |
| `local_max_size_gb` | 20 | 按 GiB 计算的图片文件容量上限，所有共用写入入口合计 |
| `local_retention_hours` | 12 | 保存时确定该文件与链接的绝对过期时间 |
| `local_cleanup_interval_hours` | 2 | 周期清理间隔；启动时补扫，容量不足时补清理已过期文件 |
| `local_alert_threshold_gb` | 2 | 剩余图片配额不超过该值时发送邮件；阈值可修改 |

两套配置分别保留。切本地不要求 S3 凭据，不读取备份凭据；切回 S3 后使用原有配置。修改参数影响后续保存，不给已签发链接延长有效期。容量降低至现有占用以下时，拒绝会继续增加占用的写入，不删除仍在有效期内的文件。已有链接到期前继续访问，即使当前已切回 S3 或停止新上传。

本地根目录属于部署配置，通过 `image_storage.local_directory` / `IMAGE_STORAGE_LOCAL_DIRECTORY` 指定；默认使用 `DATA_DIR`（容器通常 `/app/data`）下的 `image-storage`。后台不允许任意更换服务器路径，避免旧链接丢失和越界读写。更换根目录属于运维迁移，需连同文件与元数据迁移。

## 文件与链接

保留现有 key 生成逻辑：异步 `images/imgtask_…-0.png`、同步 `images/image-api_…-0.png`、代理图片的原有前缀与内容 SHA256 文件名。驱动不再次添加前缀。

独立目录保存图片对象及小型到期元数据；临时文件完成后原子替换，进程内串行核算配额。重启时从磁盘恢复占用，失败写入返回真实错误。文件名、Content-Type、大小、到期时间保存在受保护的元数据中，不写图片 Base64 到 Redis 或数据库。

下载入口固定为 `GET/HEAD /v1/image-files/*key`，在 API Key 验证之外校验 HMAC 签名与绝对到期时间。签名密钥使用持久化 JWT secret 做独立用途派生；不新增管理员需要管理的凭据。所有文件操作通过 Go `os.Root` 约束到专用目录，拒绝路径逃逸、非法 key 和非普通文件。下载通过已打开文件句柄发送，支持 HEAD / Range，并设置禁止共享缓存、nosniff 和限制内容执行的响应头。

到期后立即拒绝新的下载；正常物理删除可能滞后一个清理周期（默认最多约 2 小时）。已开始的下载或用户保存的副本无法撤回。清理仅操作本功能专用目录中的文件。清理任务独立于当前上传后端，具有启动补扫与停止钩子，不随每次设置解析重复创建 goroutine。

## 容量邮件预警

剩余配额 `max(容量上限 - 图片占用, 0)` 不超过阈值时进入低容量状态。后台检测并复用系统通知邮件模板和 SMTP 服务，收件人优先使用已启用的运维告警收件人，未配置时使用已验证且未停用的账号配额通知邮箱。无收件人或发送失败记录真实错误并保留重试机会，不影响生图。一次低容量状态只通知一次，各收件人的成功发送由现有通知服务去重；状态保存在图片专用目录，重启不重复开启同一状态。空间恢复到阈值以上后重新布防。阈值须小于本地容量上限。

## 图片代理与切换一致性

图片代理每次请求固定一次当前存储实例，缓存 key 包含存储目标的指纹，新旧后端缓存隔离。缓存有效期不超过返回签名 URL 的剩余有效期；本地缓存命中时验证签名、到期时间和文件是否存在。旧版 7 天缓存不再直接命中。OpenAI/Grok 的“去除图片 URL 参数”处理保留系统转存链接的必要签名参数。

所有既有调用继续使用 `ImageStorage.Save`，不为各渠道分别实现本地保存，不增加失败时回落 R2 的路径。沿用已有上游图片代理的失败处理；本地容量或写盘错误会明确记录，结果转存失败继续遵守原有任务失败语义。

## 开发步骤与验收

1. 扩展后端配置/后台设置与前端类型、表单、双语文案；旧 S3 设置兼容、两套配置保留、参数验证。
2. 实现本地文件存储、签名下载、配额、元数据恢复与过期清理，并接入 Wire 生命周期和下载路由。
3. 接入统一 factory 与代理缓存隔离/期限、签名参数保留，验证原有文件 key 不变。
4. 验证：旧 S3 与 local 选择、无 S3 凭据启用 local、热切换、重启与切回 S3 后旧链接、签名篡改/到期/路径逃逸、并发配额、周期清理、缓存命中与切换、后台提交及 i18n/typecheck、编译和 diff 检查。

部署前需将本地公开域名设为服务器可达的 HTTPS 域名；现有新机可使用 `https://direct.duomi.cloud`。根目录沿用现有持久化挂载。本地模式仅支持一个应用进程独占该目录；共享目录或独立磁盘的多副本均不在本次支持范围。
