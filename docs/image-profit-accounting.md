# 生图利润核算

管理员菜单“利润核算”统计余额生图调用，金额统一为美元。套餐、视频不纳入首版。不会修改用户余额或原用量记录。

- 收入：用量日志 `actual_cost`，逐笔按扣费精度 8 位小数取值后汇总。
- 成本：已有计费张数 × 调用发生时有效的每张采购单价。混合分辨率逐档计算，收入只计一次。
- 毛利：收入减采购成本；不是包含充值、支付手续费、订阅摊销的现金净利润。
- 模型：优先使用实际发往上游的 `upstream_model`，历史空值使用 `model`；不以返回模型声明替代请求模型。
- 分辨率：沿用账单 `1K/2K/4K` 档位。`image_size_breakdown` 只读取档位计数，不把缓存 Token 等附加字段当作张数。

## 采购单价

按“账号或渠道＋模型＋分辨率”新增价格版本，账号价优先于渠道默认价。价格、生效时间、备注及操作人保留，已有版本不覆盖或删除。

生效时间留空表示立即生效；时间输入固定按北京时间解释，与浏览器时区无关。价格 0 表示已确认免费采购，未知价格不得填 0。

历史成本更正：新增价格版本，填写对应历史生效时间和原因，再手动重算指定日报。同一适用范围、模型、分辨率、生效时间的多条版本，以最后新增的版本为准。新增价格本身不会修改已生成的日报。

## 每日结算与历史

服务按北京时间每日 07:00 结算昨天的自然日。启动后和每分钟检查漏算日期，每轮最多补算 14 天。07:00 前不提前自动结算昨天。跨实例使用日期事务锁；同日自动任务只生成一份日报。

日期按用量记录入账时间 `created_at` 归属，异步任务跨日时按记录的结算日。采购价按同一时间匹配。日报保留原金额、采购版本和来源用量 ID；主动重算新增日报版本和原因，可在详情中切换历史版本。

无采购价也生成待补全日报。缺价、未知分辨率、未知／不一致张数时保留收入、列出待核对项，毛利为 null，页面显示“—”。已核算成本仅代表已匹配部分。

失败不另行产生采购成本。历史用量中零扣费记录无法区分免费调用、扣款失败等情况，因此标记待核对，不擅自计采购损失或输出完整利润。

## 数据边界

本功能基于现有用量日志，不是独立现金流水。历史日志与扣款写入并非同一事务，费用日志保存精度与扣款精度也不同，极小金额可能有双重舍入差异。简单模式不运行结算。

早于当前日志可验证保留边界的日期标为源数据不足；重算若发现原日报任何来源用量 ID 缺失，拒绝重算并保留旧版。历史上从未记录或已在首次核算前删除的用量无法恢复。请保持足够的用量保留期；迟到日志可通过主动重算纳入。

数据库迁移 `250_image_profit_accounting.sql` 新增采购规则和日报表，不改原用量表。接口位于 `/api/v1/admin/profit-accounting`，受既有管理员认证与审计中间件保护。
